# Audit compliance

This Terragrunt unit deploys the audit-account compliance notification
workload. It packages a Lambda function that reads the compliance CSV report
from S3 and sends a notification to Slack.

## Components

- AWS Lambda function for processing the S3 compliance report.
- IAM role and policies for Lambda execution, S3 access, and KMS decryption.
- CloudWatch log group for Lambda logs.
- EventBridge rule and Lambda permission for the scheduled invocation.
- CloudWatch alarms for Lambda errors and execution duration.
- SNS topic used by the CloudWatch alarms.

## Terragrunt

The unit inherits its provider, common variables, account settings, and remote
state configuration from `terragrunt/audit/root.hcl`.

The remote state is stored at:

```text
s3://cds-aft-audit-production-tf/compliance/terraform.tfstate
```

The configured AWS account is `886481071419` in `ca-central-1`.

## Configuration

The Terraform configuration currently expects these inputs in addition to the
common audit inputs generated by Terragrunt:

| Name | Description |
|------|-------------|
| `environment` | Environment tag applied to resources. |
| `s3_bucket_name` | S3 bucket containing the compliance CSV report. |
| `s3_kms_key_arn` | KMS key ARN used to encrypt the report bucket. |
| `slack_webhook_url` | Slack incoming webhook used by the Lambda. |
| `schedule_expression` | EventBridge schedule for the daily compliance check. |
| `log_retention_days` | CloudWatch log retention period. |

The CI workflows pass the `COMPLIANCE_REPORT_SLACK_URL` GitHub secret to
`slack_webhook_url` for plan and apply jobs.

## Lambda source

The archive configuration expects the Lambda source at:

```text
lambdas/aws_s3_csv_to_slack
```

That directory must contain the handler configured in `lambda.tf`:

```text
app.lambda_handler
```

## Usage

From this directory:

```bash
terragrunt plan
terragrunt apply
```

The GitHub Actions workflows also include this unit in their Terraform plan
and apply matrices.

## Existing resources

Terraform will create resources that are absent from the remote state. It will
not automatically adopt resources that already exist in AWS. Import existing
resources into the `compliance/terraform.tfstate` state before running an
approved apply, or the apply may fail with resource-already-exists errors.

Before enabling apply, define all inputs, add the Lambda source directory, and
ensure the SNS topic referenced by the alarms is declared in this unit.
